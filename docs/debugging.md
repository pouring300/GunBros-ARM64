# Debugging and Diagnostics Guide: GunBros ARM64 Bridge

This guide describes how to analyze, debug and troubleshoot issues while running GunBros on modern Android devices.

---

## 1. Real-Time Logging System (Logcat)

The native bridge emits structured messages through the Android logging subsystem. Specialized tags have been defined to isolate the different components:

| Tag | Typical Level | Responsibility and Content |
| :--- | :--- | :--- |
| **`GunBros`** | `INFO` / `WARN` | General lifecycle, bridge initialization, screen resolution and touch events. |
| **`GunBrosFS`** | `DEBUG` / `INFO` | Exhaustive I/O auditing: `fopen`, `fread`, `fwrite`, `rename`, `remove`, `stat` calls, normalized paths and `errno` values. |
| **`GunBrosHLE`** | `DEBUG` / `WARN` | Interception of Bionic library functions, unimplemented routines and OpenGL ES calls. |
| **`GunBrosDyn`** | `INFO` / `ERROR` | Dynarmic state, JIT block compilation, SVC traps and exceptions from the emulated processor. |
| **`GLU`** | `INFO` | Messages printed internally by the original Glu Mobile engine. |

## 2. Capturing and Filtering Logs

### 2.1. Automated Script
To start a clean, continuous log capture and save it to a timestamped file:
```bash
./scripts/collect-logs.sh
```
The log file will be saved automatically to `logs/gunbros_YYYYMMDD_HHMMSS.log`.

### 2.2. Manual ADB Commands
If you only want to filter file operations in real time:
```bash
adb logcat -s GunBrosFS:V
```

To see the general bridge execution and possible Android errors:
```bash
adb logcat -v time GunBros:V GunBrosFS:V GunBrosHLE:V GunBrosDyn:V AndroidRuntime:E *:S
```

To clear the Logcat buffer before a new session:
```bash
adb logcat -c
```

## 3. Inspecting Saved Files on the Device

Files generated by the game are stored in the app's private directory:
```
/storage/emulated/0/Android/data/com.glu.android.gunbros_free/files/
```

### 3.1. List Files Created by the Game
```bash
adb shell ls -la /storage/emulated/0/Android/data/com.glu.android.gunbros_free/files/
```
In a typical run, you should see files such as:
- `prefs.dat` (game and audio options).
- `savegame.dat` (main save file).
- `-1_1000` to `-1_1019` (profile and statistics stores).
- `-1_PDST` (player persistence state).

### 3.2. Download the Files to Your Computer for Analysis
```bash
mkdir -p ./dump_savegame
adb pull /storage/emulated/0/Android/data/com.glu.android.gunbros_free/files/ ./dump_savegame/
```

### 3.3. Overwrite with a Test Save
```bash
adb push ./my_save/savegame.dat /storage/emulated/0/Android/data/com.glu.android.gunbros_free/files/savegame.dat
```

## 4. Diagnosing Hangs and the Watchdog

If emulation stops or a frame freezes for more than 2 seconds, the **supervisor thread (Watchdog)** prints a diagnostic dump to Logcat under the `GunBros` tag:

```text
E GunBros : [WATCHDOG] Frame execution stalled! Exceeded 2.0s timeout.
E GunBros : [WATCHDOG] Guest PC: 0x0037a4e8  Guest SP: 0x707ffec0
E GunBros : [WATCHDOG] Register Dump:
E GunBros :   r0: 0x00000000   r1: 0x6004b120   r2: 0x00000004   r3: 0x00000001
E GunBros :   r4: 0x6004b100   r5: 0x00000000   r6: 0x004c9658   r7: 0x00000000
E GunBros :   r8: 0x00000000   r9: 0x00000000  r10: 0x00000000  r11: 0x707ffef0
E GunBros :  r12: 0x80001234   lr: 0x00366880  cpsr: 0x60000010
```

### How to Interpret the Dump:
- **`Guest PC`**: Indicates the ARM32 instruction address where the code got stuck. You can cross-check this address by opening `libandroidplatform.so` in disassembly tools such as **Ghidra**, **IDA Pro** or **Rizin** to identify which function is executing.
- If the PC points to `0x8000xxxx`, execution was inside an HLE call stub. Check `hle_dispatcher.c` to identify which system call did not return control.

## 5. Common Problems and Solutions

### 5.1. "Failure [INSTALL_FAILED_DEPRECATED_SDK_VERSION]"
- **Cause**: Android 14, 15 and 16 restrict by default the installation of apps designed for old Android versions.
- **Solution**: Install using the `--bypass-low-target-sdk-block` parameter:
  ```bash
  adb install --no-incremental --bypass-low-target-sdk-block -r -d GunBros_Android16_Dynarmic.apk
  ```

### 5.2. Black Screen After the Initial Logo
- **Cause**: Failure creating the EGL surface or an OpenGL ES 1.1 CM context mismatch.
- **Diagnosis**: Check Logcat for errors with the `EGL` or `GunBros` tag:
  ```bash
  adb logcat -s GunBros:E EGL_emulation:E
  ```
- **Solution**: Make sure the device supports OpenGL ES 1.1 CM or that the vendor driver exposes the required OES extensions.

### 5.3. Touch Controls Do Not Respond at the Edges of the Screen
- **Cause**: Offset in the coordinate transformation due to the ultra-wide aspect ratio (20:9 or 21:9).
- **Solution**: The `android_window.c` module automatically calculates the black bar margins (*letterboxing*). Verify that `android_window_translate_touch` is receiving the correct physical window dimensions.
