# Persistence Debugging Protocol (Save Debugging)

This protocol makes it possible to deterministically diagnose and isolate any problem related to game progress persistence (`savegame.dat`, `prefs.dat`, `-1_1000..-1_1019`) in GunBros ARM64.

---

## Prerequisites

- Android device with USB debugging / ADB enabled.
- Log capture script: `./scripts/collect-logs.sh`.
- APK built with the `BRIDGE_DEBUG` flag enabled in CMake / the build.

---

## Step-by-Step Protocol

### Step 1: Build with `BRIDGE_DEBUG` and Prepare Logging

1. Build the project with debugging support enabled:
   ```bash
   ./scripts/build.sh
   ```
2. Install the APK on the device:
   ```bash
   ./scripts/deploy.sh
   ```
3. Start continuous log capture with `collect-logs.sh`:
   ```bash
   ./scripts/collect-logs.sh
   ```
   *(This script will filter the `GunBrosARM64` and `GunBrosFS` tags and save the output to `logs/gunbros_<timestamp>.log`).*

---

### Step 2: Session 1 — Writing Initial Progress

1. Open the game on the device.
2. Play a short match or buy an item in the store (changes coins / equipment).
3. Exit the game cleanly (or minimize it and close it from the recent tasks view).
4. Pull the game's entire data folder to your local machine:
   ```bash
   adb pull /sdcard/Android/data/com.glu.android.gunbros_free/files session1_files/
   ```
5. Compute and save the SHA-256 hashes of each generated file:
   ```bash
   sha256sum session1_files/* > session1_checksums.txt
   cat session1_checksums.txt
   ```

---

### Step 3: Session 2 — Cold Load Without Modifications

1. Open the game again from the launcher, **without touching anything** in the store or changing the inventory.
2. Wait for the main menu or the character selection screen to load.
3. Exit the game completely.
4. Pull the files folder again into a separate directory:
   ```bash
   adb pull /sdcard/Android/data/com.glu.android.gunbros_free/files session2_files/
   ```
5. Compute the new SHA-256 hashes:
   ```bash
   sha256sum session2_files/* > session2_checksums.txt
   cat session2_checksums.txt
   ```

---

### Step 4: Diagnosis and Hypothesis Analysis

Compare the hashes between Session 1 and Session 2 (`diff -u session1_checksums.txt session2_checksums.txt`):

#### Scenario A: The files changed between Session 1 and Session 2
- **Diagnosis**: The game read the files but failed internal integrity or format validation, interpreted the save as corrupt or mismatched, and overwrote them with default values on startup.
- **Required action**:
  - Check the logs for `[FS:SAVE:fread]` traces (check whether `req == got` or whether truncated reads occurred).
  - Check `[FS:SAVE:fseek]` and see whether the offsets are negative (e.g. `SEEK_END` or backward jumps).
  - Check `[FS:SAVE:stat]` to confirm that the reported size exactly matches the physical file and that the modification time (`st_mtime`) is consistent.

#### Scenario B: The files did NOT change (identical hashes)
- **Diagnosis**: The game engine never tried to read the existing files on startup, or the read path was rejected before reaching the POSIX filesystem.
- **Required action**:
  - Search the log for any `[FS:SAVE:fopen]` call with mode `"rb"` on `savegame.dat` or `prefs.dat` when the app starts.
  - Check whether any `[BRIDGE_DEBUG:JNI] OpenAPKFile called for 'data:savegame.dat'` call appears, which would indicate that the engine tried to open the file through the Java resource layer instead of the local file layer.

---

### Step 5: Hexdump Comparison

1. Compare the save files between both sessions byte by byte:
   ```bash
   xxd session1_files/savegame.dat > s1_save.hex
   xxd session2_files/savegame.dat > s2_save.hex
   diff -u s1_save.hex s2_save.hex
   ```
2. Check the log for the lines generated by `[FS:SAVE:HEXDUMP]` during `fclose` with mode `wb`:
   ```text
   [FS:SAVE:HEXDUMP] path='/.../files/savegame.dat' size=1024 first_64_bytes: 47 55 4e 42 ...
   ```
3. Use the first 64 bytes to identify whether the file contains a magic header (`GUNB`, etc.), version markers, or whether the data is in plain text or encrypted.
